# 夜あわせ — 仕様書(モック版)

作成日: 2026-09-05
対象: React Native (Expo) インタラクティブモック

---

## 1. コンセプト

**夜あわせ**は、仙台・国分町エリア限定の位置情報×MBTIマッチングアプリ。
夜の街で「いま近くにいる、相性のいい人」と店舗チェックインを起点につながる。

- **エリア限定**: 国分町エリア内でのみプロフィールが表示され、利用できる
- **匿名性重視**: ニックネームなし・性別区別なし。ユーザーは**MBTIタイプのアイコン**として表現される
- **MBTIベースのマッチング**: 相性を4段階(S/A/B/C)で診断
- **店舗チェックイン**: チェックインすると「その店にどんなタイプが多いか」がわかり、店自体にMBTIキャラが割り振られる

## 2. 用語

| 用語 | 意味 |
|---|---|
| MBTIタイプ | 16パーソナリティ(INTJ, ENFP など16種) |
| 相性ランク | S(運命級)/ A(好相性)/ B(普通)/ C(微妙)の4段階 |
| チェックイン | 店舗に「いまいる」ことを宣言する操作。同時に1店舗のみ |
| 店舗MBTIキャラ | チェックイン者のMBTI分布の最頻タイプを店に割り振ったもの |
| エリア | 国分町エリア(仙台市青葉区国分町周辺)。エリア外では利用不可 |

## 3. ユーザー属性(プロフィール)

登録時に以下の3項目のみを登録する。ニックネーム・性別・写真は**登録しない**。

| 項目 | 選択肢 | 備考 |
|---|---|---|
| 年代 | 20代前半 / 20代後半 / 30代 / 40代 / 50代以上 | プロフィールに公開。お酒提供店舗中心のため20歳以上限定 |
| 趣味 | 映画 / 音楽 / カフェ巡り / スポーツ観戦 / 旅行 / ゲーム / アウトドア / 読書 / グルメ / アート の10種から複数選択 | 3〜6個を推奨(UI上の推奨表示のみ。上限10) |
| MBTI | 16タイプから1つ | 診断は外部サイトを案内(アプリ内診断はスコープ外) |

## 4. 機能要件

### 4.1 オンボーディング(プロフィール登録・3ステップ)

1. **STEP 1/3 年代選択** — ラジオ形式で1つ選択。20歳以上限定の注意書きを表示
2. **STEP 2/3 趣味選択** — チップ形式で複数選択。「n / 10 選択中」を表示。3〜6個推奨の説明文
3. **STEP 3/3 MBTI選択** — 4×4グリッドから1つ選択。「性別は表示されません」「診断がまだの方は外部の診断サイトで」の説明文。「プロフィールを完成する」で完了しマップへ

戻るボタンで前ステップへ戻れる。完了後はアプリ再起動までプロフィール保持(メモリ内)。

### 4.2 マップ(ホーム)

- 実地図(react-native-maps)を国分町中心(約 北緯38.261 / 東経140.872)に表示。ダークスタイル
- **店舗ピン**: 店アイコン+チェックイン人数バッジ。店舗MBTIキャラが決まっている店はタイプ略称も表示。タップで店舗詳細へ
- **人アイコン**: 近くにいるユーザーをMBTIタイプの円形アイコンでプロット。タップでプロフィール詳細へ
- **エリア境界**: 国分町エリアを破線の楕円/ポリゴンで表現
- **ヘッダー**: アプリロゴ「夜あわせ」+「国分町エリア」バッジ+プロフィールアイコン
- **チェックイン中カード**(上部): 現在チェックイン中の店舗名を表示。未チェックイン時は「チェックインしていません」。タップで店舗詳細へ
- 「エリア外・利用不可」チップ: エリア外判定のUI表現(モックでは常にエリア内として動作)
- **相性バナー**(下部): 「近くに相性がいい人 n人」+ TOP3のミニアイコン。タップでマッチタブへ

### 4.3 マッチ一覧(TOP3)

- タイトル「あなたと相性がいい人」/「国分町エリア内・上位3人を表示しています」
- 凡例: `S 運命級` `A 好相性` `B 普通` `C 微妙`
- エリア内ユーザーを相性スコア順に並べ**上位3人**をカード表示
  - MBTIアイコン(ランクバッジ付き)/ MBTIタイプ名・年代 / 現在地(「BAR CIELOにいます」「徒歩3分の店にいます」)/ 趣味タグ(2個まで)/ いいねボタン(ハート)
- カードタップでプロフィール詳細へ。ハートでいいね送信(→チャット解禁)

### 4.4 相性診断ロジック(4段階)

MBTIの4軸から決定的にスコア(0〜100)とランクを算出する(モック用ヒューリスティック)。

- **基礎スコア** = 50
  - 直感/感覚(N/S)が一致: **+24** / 不一致: **−16**(価値観の土台。最重要)
  - 外向/内向(E/I)が不一致: **+12** / 一致: **+2**(エネルギーの補完)
  - 計画/柔軟(J/P)が不一致: **+6** / 一致: **+2**(生活リズムの補完)
  - 思考/感情(T/F)が一致: **+4** / 不一致: **+0**(判断基準の近さ)
  - 例: INFJ×ENFP = 50+24+12+6+4 = **96 → S**(いわゆる相性最良ペアがSになる設計)
- **ランク割り当て**(基礎スコアから): 85以上 = S / 70〜84 = A / 50〜69 = B / 50未満 = C
- **趣味ボーナス**: 共通趣味1つにつき+3(最大+9)。**総合スコア** = min(100, 基礎+ボーナス)
  - ランクは基礎スコアのみで決まる(趣味でランクは変わらない)
  - 総合スコアはTOP3の並び順・お店との相性%の算出に使う

### 4.5 店舗チェックイン

- 店舗詳細(ボトムシート風画面)に表示するもの:
  - 店名・カテゴリタグ(バー等)・「国分町エリア内・距離」
  - **このお店との相性%**: 円形リングで表示。「今いるメンバーのMBTIの組み合わせから算出した、今夜のノリの合いやすさ」= 現在チェックイン中の各ユーザーとの相性スコアの平均
  - **店舗MBTIキャラ**: チェックイン者の最頻MBTIタイプ。「この店は ENFP な夜」のような表示。チェックイン0人の店はキャラなし
  - **いまお店にいる人リスト**: MBTIアイコン / 年代・趣味 / 「n分前にチェックイン」/ 相性ランクバッジ。上位3人+「ほかn人がチェックイン中」
  - **チェックイン/解除ボタン**: 未チェックイン時は「この店にチェックインする」、チェックイン中は「チェックイン中」バッジ+「チェックインを解除する」リンク
- チェックインは同時に1店舗のみ。別の店にチェックインすると前の店は自動解除
- 自分のチェックインが店舗の人数・MBTI分布・相性%に即時反映される

### 4.6 プロフィール詳細(相手)

- 上部: 大きなMBTIカラーアイコン+右上に「S 相性:運命級」等のランクバッジ
- MBTIタイプ名・年代 / チェックイン中の店舗 / 趣味タグ
- **性格解説**: 相手のMBTIタイプの性格説明(例「ENFP: 好奇心旺盛なムードメーカー。初対面でも会話が弾みやすいタイプ」)
- **相性の理由**: 自分のタイプとの組み合わせ解説(例「INFJのあなたとは、直感的に通じ合いながらお互いにない行動力/深さを補い合える関係」)
- 注意書き「プロフィールは国分町エリア内にいる間だけ表示されます。性別は表示されません。」
- **いいねを送るボタン** + 「どちらかが『いいね』を送るとチャットができるようになります」

### 4.7 いいね・チャット

- **どちらか一方**がいいねを送った時点でチャット解禁(相互マッチ不要)
- いいね送信後、チャット一覧に相手が追加され、トーク冒頭にシステムメッセージ「いいねが届いたので、チャットができるようになりました」を表示
- トーク画面: ヘッダーに相手のMBTIアイコン・タイプ名・「相性 S・BAR CIELO」/ 吹き出し(相手=左・グレー、自分=右・コーラル)/ 送信時刻 / 入力欄+送信ボタン
- モックでは自分の送信後、相手から**ダミー自動返信**が1〜2秒後に届く
- チャット一覧タブ: 会話中の相手をリスト表示(最終メッセージ・時刻)。いいね前は空状態表示

### 4.8 プロフィール(自分)

- 自分のMBTIアイコン・タイプ名・年代・趣味タグを表示
- 各項目の変更(オンボーディング画面の再利用)導線
- チェックイン中の店舗表示

## 5. 画面一覧・遷移


## 6. データモデル(モック)

```ts
type MbtiType = 'INTJ' | 'INTP' | ... // 16種
type AgeBand = '20代前半' | '20代後半' | '30代' | '40代' | '50代以上'
type Hobby = '映画' | '音楽' | 'カフェ巡り' | 'スポーツ観戦' | '旅行'
           | 'ゲーム' | 'アウトドア' | '読書' | 'グルメ' | 'アート'
type Rank = 'S' | 'A' | 'B' | 'C'

interface Profile { ageBand: AgeBand; hobbies: Hobby[]; mbti: MbtiType }

interface Person {           // 周囲のダミーユーザー
  id: string
  mbti: MbtiType
  ageBand: AgeBand
  hobbies: Hobby[]
  venueId: string | null     // チェックイン中の店。null = 街歩き中
  checkedInAt?: number       // チェックイン時刻(分前表示に使用)
  coord: { latitude: number; longitude: number }
}

interface Venue {
  id: string
  name: string               // 例: BAR CIELO
  category: 'バー' | '居酒屋' | 'カフェ' | 'ラウンジ'
  coord: { latitude: number; longitude: number }
  distanceM: number          // 現在地からの距離(モックでは固定値)
}

interface ChatMessage {
  id: string
  personId: string
  from: 'me' | 'them' | 'system'
  text: string
  at: number
}
```

派生値(保存しない):
- 相性スコア/ランク: `compatibility(myProfile, person)` で都度計算
- 店舗の人数・MBTI分布・店舗MBTIキャラ・お店との相性%: `Person.venueId` から集計

## 7. デザイン

- **テーマ**: ダーク基調(背景 #0B0E14 付近)。アクセントはコーラルピンク(#F87171系)とティール(#2DD4BF系)
- **MBTIアイコン**: タイプ名を載せた円形バッジ。4グループで色分け
  - アナリスト(NT): ティール / 外交官(NF): レッドブラウン / 番人(SJ): ブルー / 探検家(SP): パープル
- ランクバッジ色: S=コーラル / A=ティール / B=イエロー / C=グレー
- タブバー: マップ / マッチ / チャット / プロフィール(アクティブ=コーラル)

## 8. 技術構成

| 項目 | 採用 |
|---|---|
| フレームワーク | Expo (React Native) + TypeScript |
| ナビゲーション | expo-router(タブ+スタック) |
| 地図 | react-native-maps(iOS: Apple Maps ダークモード / Android: Google Maps ダークスタイルJSON) |
| 状態管理 | zustand(メモリ内。永続化なし) |
| データ | `src/data/` の静的シード(店舗5件程度・周辺ユーザー8人程度) |
| バックエンド | モック段階ではなし。**Cloudflare Workers + Hono + D1 で実装予定**(詳細: [バックエンド仕様書](./バックエンド仕様書.md)) |

### バックエンド差し替えを見据えた構造

データ取得・更新は `src/api/` のクライアント層(例: `fetchVenues()`, `fetchNearbyPeople()`, `checkIn(venueId)`, `sendLike(personId)`, `sendMessage(...)`)に集約する。モックではこの層が静的シード+zustandを返すだけだが、バックエンド実装後は同じ関数シグネチャのままHonoのREST APIコールに差し替える。画面側はこの層のみに依存させる。

## 9. モックの制約(本実装との差分)

| 項目 | モック | 将来の本実装 |
|---|---|---|
| 位置情報 | 固定(国分町内にいる想定) | GPS実測+エリア内外判定 |
| エリア外制限 | UI表現のみ | エリア外はプロフィール非公開・機能ロック |
| ユーザー | 静的ダミー8人 | 実ユーザー(認証・年齢確認) |
| チャット | 端末内・自動返信 | リアルタイムメッセージング |
| いいね | 一方向で即チャット解禁 | 通知・ブロック/通報機能 |
| データ保持 | アプリ再起動で消える | サーバー永続化(Node.js + Hono バックエンド) |
| 法規制 | 対象外 | 出会い系サイト規制法等の要件検討(別途調査済み) |
